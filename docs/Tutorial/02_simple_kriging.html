1. Overview

Simple Kriging (SK) is the BLUE (Best Linear Unbiased Estimator) of a random field when the mean is known. It is the natural next step after variogram modeling: once spatial correlation is quantified, SK uses that model to interpolate at unsampled locations and to report a kriging standard error at every location.

This tutorial applies SK to cadmium (Cd) in the Swiss Jura using PyGStat:

Step What we do
Data Load jura_data.csv (359 samples) and jura_grid.csv (prediction nodes)
Split Stratified 70% / 30% train–test split by Landuse
Variogram Fit spherical, exponential, gaussian, Matérn, stable, and cubic models on the training set; pick the best by AIC
Simple Kriging Use the training mean as the known SK mean; fit SK with the winning variogram
Validation Predict the held-out test locations; report RMSE, MAE, \(R^2\), and mean error
Mapping Predict Cd and kriging standard error on the Jura grid
Probability Map \(P(\text{Cd} > z_c)\) for \(z_c \in \{0.10, 0.25, 0.50, 0.75, 1.00\}\) mg/kg
CPU / GPU Time SimpleKriging.predict on CPU vs GPU for Jura Cd and Great Plains SOC (gp_data_5000.csv)

By the end you will have validated SK predictions, mapped Cd and its uncertainty, produced exceedance-probability surfaces under the Gaussian SK model, and seen when a GPU pays off for SK.

2. What is Simple Kriging?

Kriging predicts \(Z(\mathbf{x}_0)\) at an unsampled location from nearby observations \(Z(\mathbf{x}_1),\ldots,Z(\mathbf{x}_n)\). All linear kriging estimators have the form of a weighted average of residuals around a mean:

\[ \hat{Z}_{\text{SK}}(\mathbf{x}_0) = m + \sum_{i=1}^{n} \lambda_i \, \bigl(Z(\mathbf{x}_i) - m\bigr) \]

where \(m = \mathbb{E}[Z(\mathbf{x})]\) is treated as known (in practice, estimated from the training data and then held fixed).

Assumptions

Assumption Meaning
Second-order stationarity Constant mean \(m\) and covariance \(C(\mathbf{h})\) that depends only on lag
Known mean \(m\) is not estimated jointly with the weights (unlike ordinary kriging)
Variogram / covariance known The spatial model \(\gamma(h)\) (or \(C(h)\)) is fitted beforehand

Simple vs ordinary kriging

Simple Kriging Ordinary Kriging
Mean Known, fixed Unknown, locally estimated
Unbiasedness Weights need not sum to 1 \(\sum \lambda_i = 1\) (Lagrange multiplier)
Kriging matrix Covariance matrix \(C\) only \(C\) augmented with a row/column of ones
When to use Stationary field with a well-estimated global mean Local mean uncertain, or a mild trend

SK typically has smaller kriging variance than OK when the mean really is known, because it does not spend a degree of freedom on estimating \(m\). If the assumed mean is wrong, SK is biased.

3. How Simple Kriging Works

3.1 From variogram to covariance

Under second-order stationarity the covariance and the variogram are linked by

\[ C(h) = C(0) - \gamma(h), \qquad C(0) = C_0 + C \]

where \(C_0\) is the nugget and \(C\) is the partial sill. PyGStat restores \(C(0)\) on the diagonal of the kriging matrix so the nugget is not dropped.

3.2 The SK linear system

The weights \(\boldsymbol{\lambda}\) that minimise the mean squared prediction error solve

\[ \mathbf{C}\,\boldsymbol{\lambda} = \mathbf{c}_0 \]

where \(C_{ij} = C(\mathbf{x}_i - \mathbf{x}_j)\) among training points and \(c_{0,i} = C(\mathbf{x}_0 - \mathbf{x}_i)\) between the target and each training point. Then

\[ \hat{Z}_{\text{SK}}(\mathbf{x}_0) = m + \boldsymbol{\lambda}^\top \bigl(\mathbf{z} - m\mathbf{1}\bigr). \]

3.3 Kriging variance (prediction error)

The SK variance at \(\mathbf{x}_0\) is

\[ \sigma^2_{\text{SK}}(\mathbf{x}_0) = C(0) - \boldsymbol{\lambda}^\top \mathbf{c}_0. \]

PyGStat’s predict(..., return_variance=True) returns the standard error \(\sigma_{\text{SK}} = \sqrt{\sigma^2_{\text{SK}}}\). This is the map of prediction error used later in this notebook.

3.4 Gaussian exceedance probability

If the SK predictor is treated as Gaussian, \(Z(\mathbf{x}_0)\,|\,\text{data} \sim \mathcal{N}\bigl(\hat{Z}_{\text{SK}},\,\sigma^2_{\text{SK}}\bigr)\), then the probability of exceeding a cutoff \(z_c\) is

\[ P\bigl(Z(\mathbf{x}_0) > z_c\bigr) = 1 - \Phi\!\left(\frac{z_c - \hat{Z}_{\text{SK}}(\mathbf{x}_0)}{\sigma_{\text{SK}}(\mathbf{x}_0)}\right). \]

This is a parametric probability map. It is convenient and consistent with SK, but it inherits the Gaussian assumption. Indicator kriging (a later tutorial) estimates the same probabilities without assuming a Gaussian law.

3.5 Workflow in this notebook

  1. Split samples by Landuse so every land-use class appears in both train and test.
  2. Estimate \(\gamma(h)\) from training Cd only (no leakage from the test set).
  3. Take \(m = \overline{\text{Cd}}_{\text{train}}\) as the known SK mean.
  4. Solve the SK system at test locations → validation metrics.
  5. Solve the SK system at every Jura grid node → maps of \(\hat{Z}\) and \(\sigma_{\text{SK}}\).
  6. Convert \((\hat{Z},\sigma_{\text{SK}})\) into \(P(\text{Cd} > z_c)\) at five cutoffs.

4. Python Setup

4.1 CPU and GPU

PyGStat’s SimpleKriging builds the covariance matrix and solves the kriging system on CPU (NumPy/SciPy) or GPU (CuPy). Pass use_gpu as:

Value Behaviour
'auto' (default) GPU when CuPy can run a kernel on this card. Falls back to CPU otherwise.
True Force GPU. Warns and falls back to CPU if CuPy is missing or cannot run a kernel.
False Always CPU (NumPy/SciPy).

This notebook probes the GPU once with cupy_gpu_usable() (a real op, not just import cupy) and stores the result in USE_GPU. The SK fit below passes use_gpu=USE_GPU, so the same cells run on a laptop CPU or a CUDA workstation without edits.

Two caveats:

  • The Matérn model always evaluates on CPU (SciPy Bessel functions have no CuPy equivalent). The SK linear algebra is still GPU-accelerated when USE_GPU is true.
  • Small \(n\) (a few hundred training points, like Jura) often shows little GPU gain unless you predict a large grid: host→device copies and kernel-launch overhead can dominate a small \(n \times n\) system.

Install CuPy with pip install pygstat[gpu] (CUDA 11) or pip install cupy-cuda12x for CUDA 12.

Section 13 times SimpleKriging.predict on both backends using Jura Cd and prefixes of data/gp_data_5000.csv.

7. Variogram Modeling on Training Data

We fit all six PyGStat models to the training Cd values with the Matheron estimator, then rank them by AIC (Tutorial 02). The winning model is the covariance structure used for simple kriging.

Code 
def find_best_variogram(coords, values, estimator="matheron", n_lags=15,
                        criterion="AIC", verbose=True):
    """Fit all standard models; return the best Variogram by ``criterion``."""
    models = ["spherical", "exponential", "gaussian", "matern", "stable", "cubic"]
    n_params = {"spherical": 3, "exponential": 3, "gaussian": 3,
                "matern": 4, "stable": 4, "cubic": 3}
    fitted, records = {}, []

    for model_name in models:
        v = Variogram(coords=np.asarray(coords, dtype=float),
                      values=np.asarray(values, dtype=float),
                      model=model_name, estimator=estimator, n_lags=n_lags)
        v.fit()
        obs = v.experimental
        mask = ~np.isnan(obs)
        obs_v, pred = obs[mask], v(v.lags)[mask]
        K, p = mask.sum(), n_params[model_name]
        rss = float(np.sum((pred - obs_v) ** 2))
        tss = float(np.sum((obs_v - obs_v.mean()) ** 2))
        r2 = 1.0 - rss / tss if tss > 0 else np.nan
        aic = K * np.log(rss / K) + 2 * p if rss > 0 else -np.inf
        bic = K * np.log(rss / K) + p * np.log(K) if rss > 0 else -np.inf
        fitted[model_name] = v
        extra = round(float(v.fitted_params[3]), 4) if len(v.fitted_params) > 3 else "—"
        records.append({
            "Model": model_name.capitalize(),
            "Nugget": round(float(v.fitted_params[0]), 5),
            "Sill":   round(float(v.fitted_params[1]), 5),
            "Range":  round(float(v.fitted_params[2]), 5),
            "Extra":  extra,
            "RSS":    round(rss, 6),
            "R²":     round(r2, 4),
            "AIC":    round(aic, 4),
            "BIC":    round(bic, 4),
        })

    df_results = pd.DataFrame(records).set_index("Model")
    df_results = df_results.sort_values(criterion, ascending=(criterion != "R²"))
    best_cap = df_results.index[0]
    best_key = best_cap.lower()
    if verbose:
        print(df_results.to_string())
        print(f"\n>>> BEST MODEL: {best_cap} (by {criterion}) <<<")
    return best_cap, fitted[best_key], df_results, fitted

12. Probability Maps of Exceedance

Under the Gaussian SK model,

\[ P(\text{Cd}(\mathbf{x}_0) > z_c) = 1 - \Phi\!\left(\frac{z_c - \hat{Z}_{\text{SK}}(\mathbf{x}_0)}{\sigma_{\text{SK}}(\mathbf{x}_0)}\right). \]

We map this probability for cutoffs 0.10, 0.25, 0.50, 0.75, and 1.00 mg/kg. Values near 1 mean Cd is almost surely above the cutoff; values near 0 mean it is almost surely below.

Because the sample mean of Cd is about 1.3 mg/kg, probabilities of exceeding 0.10–0.75 mg/kg will be high over much of the domain. The 1.00 mg/kg map is the most spatially informative of this set.

Code 
cutoffs = [0.10, 0.25, 0.50, 0.75, 1.00]   # mg/kg

13. CPU vs GPU SK Timing

Section 4.1 showed how to select a backend. Here we measure how long simple kriging takes on CPU (use_gpu=False, NumPy/SciPy) versus GPU (use_gpu=True, CuPy) — first on the Jura samples (\(n_{\text{train}} = 359\)) predicting the Jura grid, then on prefixes of the Great Plains soil-organic-carbon survey (data/gp_data_5000.csv, \(n\) up to 5{,}000).

The GPU-accelerated steps are the \(n \times n\) covariance matrix among training points, the \(n_{\text{pred}} \times n\) covariance to the targets, and the linear solve. Variogram fitting is done once per dataset (spherical model) and is not included in the SK times.

Two practical notes:

  • Small \(n\) and few targets (a few hundred training and prediction points) often shows little GPU gain: host→device copies and kernel-launch overhead dominate.
  • Larger \(n\), or a dense prediction grid, is where the GPU pays off: the SK system scales as \(O(n^3)\) for the solve and \(O(n \cdot n_{\text{pred}})\) for the target covariances.

Each timing is the median of three SimpleKriging.fit + predict(..., return_variance=True) calls after a short GPU warmup so CUDA kernel compilation is not counted. If CuPy cannot run a kernel here, the GPU column is skipped and only CPU times are reported.

Code 
import time

N_LAGS = 12
N_REPEATS = 3
N_PRED_GP = 500
GP_SIZES = [500, 1000, 2000, 4000, 5000]

df_gp = pd.read_csv("../data/gp_data_5000.csv")
gp_coords = df_gp[["x", "y"]].to_numpy(dtype=float)
gp_vals = df_gp["SOC"].to_numpy(dtype=float)
rng = np.random.default_rng(42)


def _fit_spherical(xy, values, use_gpu=False):
    return Variogram(
        np.asarray(xy, dtype=float),
        np.asarray(values, dtype=float),
        model="spherical",
        n_lags=N_LAGS,
        use_gpu=use_gpu,
    ).fit()


def _time_sk(xy_train, z_train, xy_pred, vg, use_gpu, repeats=N_REPEATS, warmup=True):
    """Median wall time of SimpleKriging.fit + predict(return_variance=True)."""
    mean = float(np.mean(z_train))
    if warmup:
        k_tr = min(40, len(xy_train))
        k_pr = min(40, len(xy_pred))
        SimpleKriging(vg, mean=mean, use_gpu=use_gpu).fit(
            xy_train[:k_tr], z_train[:k_tr]
        ).predict(xy_pred[:k_pr], return_variance=True)
        if use_gpu:
            import cupy as cp
            cp.cuda.Device(0).synchronize()
    times = []
    last = None
    for _ in range(repeats):
        t0 = time.perf_counter()
        sk_m = SimpleKriging(vg, mean=mean, use_gpu=use_gpu).fit(xy_train, z_train)
        last = sk_m.predict(xy_pred, return_variance=True)
        if use_gpu:
            import cupy as cp
            cp.cuda.Device(0).synchronize()
        times.append(time.perf_counter() - t0)
    return float(np.median(times)), last

14. Summary and Conclusions

This tutorial walked through a complete simple kriging workflow for Jura cadmium.

What we did

  1. Split 359 samples 70 / 30 with stratified random sampling by Landuse, so rare land-use class 4 is represented in both sets.
  2. Fitted six theoretical variograms on training Cd only and selected the best model by AIC.
  3. Fitted Simple Kriging with known mean \(m = \overline{\text{Cd}}_{\text{train}}\) (use_gpu=USE_GPU).
  4. Validated at held-out locations (RMSE, MAE, mean error, \(R^2\), residual maps, standardized residuals).
  5. Mapped SK predictions and kriging standard errors on jura_grid.csv.
  6. Converted \((\hat{Z},\sigma_{\text{SK}})\) into Gaussian exceedance probabilities at 0.10, 0.25, 0.50, 0.75, and 1.00 mg/kg, and checked them on the test set with the Brier score.
  7. Timed SK on CPU vs GPU for Jura Cd and prefixes of gp_data_5000.csv.

Practical takeaways

  • Do not leak the test set into the variogram or the SK mean. Both must come from training data.
  • SK is appropriate when a global mean is credible. If Cd has a strong trend with land use or rock type, ordinary or universal kriging (or regression kriging) is usually a better next step.
  • The prediction-error map is not a map of Cd — it is a map of how well the data constrain the estimate.
  • Gaussian \(P(\text{Cd} > z_c)\) is a convenient SK by-product. Cd is right-skewed, so these probabilities are an approximation. For a distribution-free alternative, use indicator kriging.

Next steps

  • Ordinary kriging (unknown local mean) on the same split, and compare test RMSE with SK
  • Indicator kriging for the same five cutoffs without the Gaussian assumption
  • Sequential Gaussian simulation to map uncertainty beyond the SK variance
